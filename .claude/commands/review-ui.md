# UI をレビューする

## 準備
変更した画面・コンポーネントを特定し、該当ファイルを読む。

## チェック観点（各項目に ✅/⚠️/❌ を付ける）
### 空状態・エラー・ローディング
- 0 件のとき何も出ずに終わっていないか／ローディング・エラーが画面に出るか
### 操作要素のラベル
- ボタン・入力欄に押せる・入力できると分かるラベルがあるか（`aria-label` 含む）
### 操作の流れと確定タイミング
- 操作が期待どおり動くか／バリデーションはいつ出るか／取り消せない操作の前に確認するか
### 視覚的フィードバック
- 操作後の状態変化が画面でわかるか／押せないものが押せそうに見えないか

## 出力形式
各観点を見出し付きで列挙し、問題は該当ファイルと行番号を添える。
最後に「表示確認の手順」を一言（`pnpm dev` → 操作 → 期待結果）で添える。
