# API をレビューする
変更された API について、次の観点で確認してください。
- crud層のドメインエラー（重複・空値など）は例外を投げず文字列定数（DUPLICATE/EMPTY等）で返し、router層でHTTPExceptionに変換しているか（api.md）
- チェックインの重複投稿はエラーにせず無視されるか（冪等）。カテゴリの空文字は「未分類」に正規化されるか（frontendとは独立にAPI側でも判定）
- レスポンスのフィールド名はcamelCase、DB/モデル側はsnake_caseのままで、変換がschemaに書かれているか
- 取得・更新・削除は現在のユーザーが所有するデータだけに絞られているか。user_idなどをリクエスト入力から受け取らず、トークンから決めているか（security.md）
- 認証処理が各ルートに個別実装されず、共通処理にまとまっているか
- モデルを変更した場合、対応するマイグレーションを作成したか（uv run --directory api alembic check で確認できる）
- テストはTestClientでHTTPレスポンス（ステータスコード・JSON）を検証し、crud関数を直接呼んでいないか。認証が必要なテストはauth_headersフィクスチャで実際に登録・ログインしているか
- 他ユーザーのデータに触れられないことを確認するテストがtest_habit_isolation.pyにまとまっているか。テスト名は日本語で「条件→期待結果」の順になっているか
- 動作確認の手順（uv run --directory api pytest -q など）を一言添える
